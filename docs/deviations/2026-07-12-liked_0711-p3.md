# liked_0711 P3 deviations and design decisions

## #2 — browse surface: dedicated HTTP endpoint

Chosen: `GET /api/personalities/external?sources=agency-agents&q=`. The source is
off by default and enabled explicitly, matching the external-skill toggle
discipline while keeping the local DB/MCP path in `loopskill_catalog.py`
unchanged. External results are labeled `agency-agents`, `MIT`, and
`community · as-is`; browse responses omit `system_prompt`.

Deviation from the alternative: external personalities are not merged into
`loopskill_search_personalities`. That function is a local, skill-independent
DB registry path, and changing its result contract and network behavior would
have a larger blast radius than a separate personality-native endpoint.

## #5 — heartable bridge: deferred; no local materialization

P1's like contract accepts a UUID and persists personalities through
`BundlePersonality.personality_id`, a foreign key to a local `Personality` row.
An external slug therefore cannot be liked honestly today. Creating placeholder
rows would require fake or copied `system_prompt` content, mix external entries
into local browse, and violate P3's link-not-rehost architecture.

The thinnest honest bridge is a future dedicated join keyed by
`(bundle_id, source, external_slug)` with `added_at`, plus source-aware HTTP/MCP
like inputs and a library-shelf union that resolves current metadata through
the external source cache. This is a migration and cross-contract change, not a
small P3 patch, so it is explicitly flagged rather than built blind.

## Other deviations

None. Browse is TTL-cached in process for one hour; install always re-fetches
the exact upstream Markdown and runs the existing external-body scanner before
returning the prompt. No curated DB rows or sync jobs are created.
